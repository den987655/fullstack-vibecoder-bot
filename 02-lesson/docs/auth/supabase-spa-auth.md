# Поток авторизации Supabase Auth в Single Page Application (SPA)Подробное руководство и диаграмма последовательности (Sequence Diagram), описывающие, как устроен жизненный цикл авторизации и работы с токенами в **Supabase Auth (GoTrue)** при использовании `@supabase/supabase-js` в клиентских приложениях (React / Vue / Svelte / Vite).---## 1. Ключевые компоненты архитектуры Supabase в SPA```+-----------------------------------------------------------------------------------+|                            Клиент (Браузер / SPA)                                 ||                                                                                   ||  [ React / Vue UI ] <--> [ supabase.auth.onAuthStateChange ]                     ||          |                               ^                                        ||          v                               |                                        ||  [ @supabase/supabase-js ] ---> [ Auto-Refresh Timer (~60s до exp / onFocus) ]     ||          |                               |                                        ||          +------------> [ LocalStorage: sb-<ref>-auth-token ]                     |+------------------------------------------+----------------------------------------+                                           | HTTPS                                           v+-----------------------------------------------------------------------------------+|                               Платформа Supabase                                  ||                                                                                   ||  +------------------------+   +------------------------+   +-------------------+  ||  |  GoTrue Auth Service   |   |     PostgREST API      |   | Realtime Engine   |  ||  |     (/auth/v1)         |   |      (/rest/v1)        |   |   (WebSockets)    |  ||  +-----------+------------+   +-----------+------------+   +---------+---------+  ||              |                            |                          |            ||              v                            v                          v            ||  +-----------------------------------------------------------------------------+  ||  |                             PostgreSQL Database                             |  ||  |  - auth.users (пользователи)             - public.* (таблицы приложения)    |  ||  |  - auth.sessions / refresh_tokens       - Row Level Security (RLS) policies|  ||  |  - auth.uid(), auth.jwt(), auth.role()  - Realtime CDC (WAL)               |  ||  +-----------------------------------------------------------------------------+  |+-----------------------------------------------------------------------------------+```### Основные участники:1. **`@supabase/supabase-js` (GoTrueClient)**:   - Клиентская библиотека, управляющая сессией, токенами, автообновлением и запросами к API.2. **`LocalStorage` браузера**:   - По умолчанию сохраняет сессию по ключу `sb-<project_ref>-auth-token` (`access_token`, `refresh_token`, `expires_at`, `user`).3. **Supabase Auth (GoTrue)** (`/auth/v1`):   - Автономный сервис аутентификации на Go. Управляет пользователями, шифрованием паролей, выдачей JWT и ротацией refresh-токенов.4. **PostgREST** (`/rest/v1`):   - Преобразует HTTP-запросы в SQL. Принимает заголовок `Authorization: Bearer <access_token>`, распаковывает JWT и устанавливает переменные сессии PostgreSQL для **Row Level Security (RLS)**.5. **PostgreSQL + RLS**:   - База данных, где права доступа проверяются на уровне строк на основе функций `auth.uid()` и `auth.role()`.---## 2. Диаграмма последовательности (Sequence Diagram)```mermaidsequenceDiagram    autonumber    actor User as Пользователь    box rgb(245, 247, 250) Клиентское приложение (React / Vite SPA)        participant UI as React UI        participant Client as Supabase Client (@supabase/supabase-js)        participant Storage as LocalStorage    end box    box rgb(238, 250, 246) Платформа Supabase        participant GoTrue as GoTrue Auth (/auth/v1)        participant PostgREST as PostgREST API (/rest/v1)        participant PG as PostgreSQL (auth + public + RLS)    end box    %% -------------------------------------------------------------    rect rgb(235, 245, 255)    Note over User, PG: 1. Инициализация приложения и восстановление сессии    User->>UI: Открытие приложения в браузере    UI->>Client: createClient(SUPABASE_URL, ANON_KEY)    Client->>Storage: Чтение ключа "sb-<ref>-auth-token"    alt Сессия есть в хранилище        Storage-->>Client: { access_token, refresh_token, expires_at, user }        Client->>Client: Проверка срока годности exp и установка фонового таймера        Client-->>UI: emit onAuthStateChange('INITIAL_SESSION', session)        UI-->>User: Личный кабинет (пользователь уже авторизован)    else Сессия отсутствует        Storage-->>Client: null        Client-->>UI: emit onAuthStateChange('INITIAL_SESSION', null)        UI-->>User: Гостевой экран / Форма логина    end    end    %% -------------------------------------------------------------    rect rgb(240, 255, 240)    Note over User, PG: 2. Вход по паролю (Sign In with Password)    User->>UI: Ввод email и пароля, клик «Войти»    UI->>Client: supabase.auth.signInWithPassword({ email, password })    Client->>GoTrue: POST /auth/v1/token?grant_type=password<br/>Headers: apikey: ANON_KEY<br/>Body: { email, password }    GoTrue->>PG: SELECT * FROM auth.users WHERE email = ?    PG-->>GoTrue: Данные пользователя и хэш пароля    GoTrue->>GoTrue: Валидация хэша пароля (Argon2 / bcrypt)    Note over GoTrue: Генерация токенов:<br/>1. Access Token: JWT (exp = 3600с) с claims sub: userId, role: authenticated<br/>2. Refresh Token: криптографическая случайная строка    GoTrue->>PG: INSERT INTO auth.sessions, auth.refresh_tokens    PG-->>GoTrue: Сессия записана в БД    GoTrue-->>Client: 200 OK { access_token, refresh_token, expires_in: 3600, user }    Client->>Storage: Сохранение сессии в LocalStorage    Client->>Client: Запуск фонового таймера автообновления (~60 сек до exp)    Client-->>UI: emit onAuthStateChange('SIGNED_IN', session)    UI-->>User: Переход на главную страницу приложения    end    %% -------------------------------------------------------------    rect rgb(255, 250, 235)    Note over User, PG: 3. Выполнение запросов к БД с применением RLS    User->>UI: Запрос данных (например, список статей)    UI->>Client: supabase.from('articles').select('*')    Client->>PostgREST: GET /rest/v1/articles?select=*<br/>Headers:<br/>- apikey: ANON_KEY<br/>- Authorization: Bearer <access_token>        PostgREST->>PostgREST: Проверка подписи JWT через JWT_SECRET / JWKS<br/>Извлечение sub (userId) и role    Note over PostgREST, PG: PostgREST открывает транзакцию PostgreSQL:<br/>SET LOCAL request.jwt.claims = '{"sub":"...", "role":"authenticated"}';<br/>SET LOCAL role = 'authenticated';    PostgREST->>PG: SELECT * FROM articles WHERE (auth.uid() = user_id)    PG-->>PostgREST: Отфильтрованные строки таблицы    PostgREST-->>Client: 200 OK [ { id: 1, title: '...' } ]    Client-->>UI: Ответ с данными    UI-->>User: Отображение данных пользователю    end    %% -------------------------------------------------------------    rect rgb(240, 248, 255)    Note over User, PG: 4. Упреждающее фоновое обновление токена (Proactive Auto-Refresh)    Note over Client: Клиент НЕ ждет ошибки 401!<br/>Внутренний таймер срабатывает:<br/>1. За ~60 сек до exp access_token<br/>2. При возврате фокуса на вкладку браузера (visibilitychange)    Client->>GoTrue: POST /auth/v1/token?grant_type=refresh_token<br/>Headers: apikey: ANON_KEY<br/>Body: { refresh_token: <current_refresh_token> }    GoTrue->>PG: Проверка токена в auth.refresh_tokens    PG-->>GoTrue: Токен валиден, сессия активна    Note over GoTrue: Refresh Token Rotation (RTR):<br/>1. Старый refresh-токен отзывается<br/>2. Выпускается НОВАЯ пара: новый JWT + новый refresh_token    GoTrue->>PG: UPDATE auth.refresh_tokens SET revoked = true ...<br/>INSERT INTO auth.refresh_tokens (new_token)    PG-->>GoTrue: Запись обновлена    GoTrue-->>Client: 200 OK { access_token: <new_jwt>, refresh_token: <new_refresh>, expires_in: 3600 }    Client->>Storage: Перезапись новой сессии в LocalStorage    Client->>Client: Перезапуск таймера автообновления на 3600 сек    Client-->>UI: emit onAuthStateChange('TOKEN_REFRESHED', session)    Note over UI, User: Запросы пользователя продолжают выполняться бесшовно    end    %% -------------------------------------------------------------    rect rgb(255, 235, 235)    Note over User, PG: 5. Обнаружение повторного использования (Token Reuse Detection)    Note over GoTrue: Сценарий компрометации:<br/>Злоумышленник пытается использовать старый Refresh Token,<br/>который уже был ротирован легитимным клиентом    GoTrue->>PG: Поиск токена в auth.refresh_tokens -> Токен УЖЕ ОТОЗВАН!    Note over GoTrue, PG: Тревога: Обнаружена попытка повторного использования (Reuse)!<br/>Аннулирование ВСЕЙ семьи токенов сессии данного пользователя    GoTrue->>PG: DELETE FROM auth.sessions WHERE id = session_id    PG-->>GoTrue: Сессии удалены    GoTrue-->>Client: 400 Bad Request { error: "invalid_grant", message: "Invalid Refresh Token: Already Used" }    Client->>Storage: Удаление ключа сессии    Client->>Client: Остановка таймеров    Client-->>UI: emit onAuthStateChange('SIGNED_OUT', null)    UI-->>User: Редирект на экран входа (Сессия скомпрометирована)    end    %% -------------------------------------------------------------    rect rgb(245, 245, 245)    Note over User, PG: 6. Выход из системы (Sign Out)    User->>UI: Клик «Выйти»    UI->>Client: supabase.auth.signOut()    Client->>GoTrue: POST /auth/v1/logout<br/>Header: Authorization: Bearer <access_token>    GoTrue->>PG: Удаление сессии из auth.sessions    PG-->>GoTrue: Сессия удалена    GoTrue-->>Client: 204 No Content    Client->>Storage: Очистка LocalStorage    Client->>Client: Остановка таймеров автообновления    Client-->>UI: emit onAuthStateChange('SIGNED_OUT', null)    UI-->>User: Экран авторизации    end```---## 3. Отличия схемы Supabase в SPA от традиционной бэкенд-схемы| Параметр | Традиционная схема (Custom Backend) | Supabase Auth в SPA || :--- | :--- | :--- || **Стратегия обновления токена** | **Реактивная (Reactive)**: ждет получения ошибки `401 Unauthorized`, перехватывает ее в Interceptor, ставит запросы в очередь и обновляет токен. | **Упреждающая (Proactive)**: клиент заранее запускает фоновый таймер за ~60 сек до истечения срока JWT. Пользовательские запросы почти никогда не сталкиваются с 401. || **Хранение Refresh Token** | Часто в `HttpOnly` Cookie. | В `LocalStorage` браузера (или `AsyncStorage` в React Native, либо кастомный адаптер `storage` в настройках `createClient`). || **Валидация авторизации** | Бэкенд-контроллер или API Gateway. | **PostgREST + PostgreSQL RLS**: база данных сама фильтрует строки по `auth.uid()`, извлекая ID пользователя прямо из JWT. || **Подписка на статус** | Самописные события (EventEmitter / Redux / Zustand). | Встроенный стрим событий: `supabase.auth.onAuthStateChange((event, session) => ...)`. || **Ротация Refresh-токенов** | Требует отдельной реализации логики на бэкенде. | Встроена «из коробки» (RTR + немедленный отзыв сессии при попытке повторного использования). |---## 4. Практическая интеграция в Frontend### 1. Инициализация клиента (`supabaseClient.ts`)```typescriptimport { createClient } from '@supabase/supabase-js';const supabaseUrl = import.meta.env.VITE_SUPABASE_URL;const supabaseAnonKey = import.meta.env.VITE_SUPABASE_ANON_KEY;export const supabase = createClient(supabaseUrl, supabaseAnonKey, {  auth: {    persistSession: true,      // Сохранять ли сессию в storage (по умолчанию true)    autoRefreshToken: true,    // Упреждающее обновление токена в фоне (по умолчанию true)    detectSessionInUrl: true,  // Автоматический перехват токенов из hash/query (OAuth / Magic Link)    flowType: 'pkce',          // Рекомендуемый стандарт для SPA (Proof Key for Code Exchange)  },});```### 2. Подписка на изменение состояния авторизации (React Hook)```typescriptimport { useEffect, useState } from 'react';import type { Session, User } from '@supabase/supabase-js';import { supabase } from '@/shared/api/supabaseClient';export function useAuth() {  const [session, setSession] = useState<Session | null>(null);  const [user, setUser] = useState<User | null>(null);  const [loading, setLoading] = useState(true);  useEffect(() => {    // 1. Получение текущей активной сессии из хранилища    supabase.auth.getSession().then(({ data: { session } }) => {      setSession(session);      setUser(session?.user ?? null);      setLoading(false);    });    // 2. Подписка на жизненный цикл сессии    const { data: { subscription } } = supabase.auth.onAuthStateChange(      (_event, session) => {        setSession(session);        setUser(session?.user ?? null);        setLoading(false);      }    );    return () => {      subscription.unsubscribe();    };  }, []);  return { session, user, loading, isAuthenticated: !!session };}```---## 5.
