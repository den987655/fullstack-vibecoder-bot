# Навык: Авторизация пользователей и защита Supabase Edge Functions## КонтекстИспользуйте этот навык при реализации входа пользователей в систему, управления жизненным циклом токенов (Access / Refresh), передачи токена с фронтенда и защиты эндпоинтов Supabase Edge Functions (Deno).---## Основные принципы1. **Единый источник сессии (GoTrue Client)**:   - Сессия и токены управляются библиотекой `@supabase/supabase-js`.   - Токены хранятся в `LocalStorage` браузера по ключу `sb-<project_ref>-auth-token`.   - Вся система реагирует на изменения через подписку `supabase.auth.onAuthStateChange((event, session) => ...)`.2. **Упреждающее обновление токена (Proactive Auto-Refresh)**:   - Включается опцией `autoRefreshToken: true`.   - Клиент сам обновляет короткоживущий JWT токен за ~60 секунд до его истечения или при возврате фокуса на вкладку (`visibilitychange`).   - Запросы к API не сталкиваются с внезапными ошибками 401.3. **Динамическая передача User JWT в HTTP-запросах**:   - Анонимный ключ (`apikey`) идентифицирует проект Supabase.   - Заголовок `Authorization: Bearer <access_token>` передает токен конкретного авторизованного пользователя, полученный из `supabase.auth.getSession()`.4. **Защита Edge Functions (`requireAuth`)**:   - Edge Functions в Deno извлекают заголовок `Authorization`.   - Проверяют подлинность JWT через `auth.getUser(token)`.   - Анонимный ключ (`anonKey`) отклоняется со статусом 401, если функция требует учетную запись пользователя.   - Клиент базы данных создается с заголовком пользователя для соблюдения **Row Level Security (RLS)**.---## Руководство по реализации### 1. Защита Supabase Edge Functions (`_shared/auth.ts`)Создайте переиспользуемый модуль в каталоге `supabase/functions/_shared/auth.ts`:```typescriptimport { createClient, type User } from "npm:@supabase/supabase-js@2";export const corsHeaders = {  "Access-Control-Allow-Origin": "*",  "Access-Control-Allow-Headers": "authorization, x-client-info, apikey, content-type",  "Access-Control-Allow-Methods": "GET, POST, PUT, PATCH, DELETE, OPTIONS",};export interface AuthContext {  user: User;  token: string;  supabaseClient: ReturnType<typeof createClient>;}export async function requireAuth(req: Request): Promise<AuthContext> {  const authHeader = req.headers.get("Authorization");  if (!authHeader || !authHeader.startsWith("Bearer ")) {    throw new Response(      JSON.stringify({        error: "Требуется авторизация: заголовок Authorization отсутствует",        code: "UNAUTHORIZED",      }),      {        status: 401,        headers: { ...corsHeaders, "Content-Type": "application/json" },      }    );  }  const token = authHeader.replace(/^Bearer\s+/i, "").trim();  const supabaseAnonKey = Deno.env.get("SUPABASE_ANON_KEY") ?? "";  const supabaseUrl = Deno.env.get("SUPABASE_URL") ?? "";  // Отклоняем вызов, если передан только anon key  if (token === supabaseAnonKey) {    throw new Response(      JSON.stringify({        error: "Доступ запрещен: требуется токен пользователя, а не анонимный ключ",        code: "USER_TOKEN_REQUIRED",      }),      {        status: 401,        headers: { ...corsHeaders, "Content-Type": "application/json" },      }    );  }  // Проверка валидности токена  const authClient = createClient(supabaseUrl, supabaseAnonKey);  const { data: { user }, error: authError } = await authClient.auth.getUser(token);  if (authError || !user) {    throw new Response(      JSON.stringify({        error: `Доступ запрещен: ${authError?.message || "недействительный или истекший токен"}`,        code: "INVALID_TOKEN",      }),      {        status: 401,        headers: { ...corsHeaders, "Content-Type": "application/json" },      }    );  }  // Клиент, выполняющий запросы от лица авторизованного пользователя (с учетом RLS)  const supabaseClient = createClient(supabaseUrl, supabaseAnonKey, {    global: { headers: { Authorization: authHeader } },  });  return { user, token, supabaseClient };}```### 2. Использование `requireAuth` в Edge Function (`index.ts`)```typescriptimport { corsHeaders, requireAuth } from "../_shared/auth.ts";Deno.serve(async (req: Request) => {  if (req.method === "OPTIONS") {    return new Response("ok", { headers: corsHeaders });  }  try {    // Вызов requireAuth защищает функцию и возвращает данные пользователя    const { user, supabaseClient } = await requireAuth(req);    // Работа с БД с контекстом пользователя    const { data, error } = await supabaseClient.from("articles").select("*");    if (error) throw error;    return new Response(JSON.stringify(data), {      headers: { ...corsHeaders, "Content-Type": "application/json" },      status: 200,    });  } catch (error: any) {    if (error instanceof Response) {      return error; // Возвращаем 401 с заголовками CORS    }    return new Response(JSON.stringify({ error: error.message }), {      headers: { ...corsHeaders, "Content-Type": "application/json" },      status: 500,    });  }});```### 3. Автоматическая подстановка токена на фронтенде (`shared/api/base.ts`)```typescriptimport { supabase } from './supabaseClient';export const fetchApi = async <T>(endpoint: string, options?: RequestInit): Promise<T> => {  const url = `${API_BASE_URL}${endpoint}`;  const headers: Record<string, string> = { 'Content-Type': 'application/json' };  const anonKey = import.meta.env.VITE_SUPABASE_ANON_KEY;  if (anonKey) {    headers['apikey'] = anonKey;    headers['Authorization'] = `Bearer ${anonKey}`;  }  // Если есть активная сессия пользователя, подставляем его JWT токен  try {    const { data: { session } } = await supabase.auth.getSession();    if (session?.access_token) {      headers['Authorization'] = `Bearer ${session.access_token}`;    }  } catch {    // Фоллбэк на анонимный ключ  }  if (options?.headers) Object.assign(headers, options.headers);  const response = await fetch(url, { ...options, headers });  if (!response.ok) {    const errData = await response.json().catch(() => ({}));    throw new Error(errData.error || errData.message || 'Ошибка запроса');  }  return response.json();};```### 4. Вход пользователя и состояние (`authStore.ts`)```typescriptsignIn: async (email: string, password: string) => {  const { data, error } = await supabase.auth.signInWithPassword({    email: email.trim(),    password,  });  if (error) return { error: error.message };  return { error: null };}```---## Чек-лист проверки авторизации- [ ] Заголовок `OPTIONS` возвращает статус 200 и CORS-заголовки `authorization, apikey, content-type`.- [ ] При отсутствии заголовка `Authorization` Edge Function возвращает HTTP 401 (`UNAUTHORIZED`).- [ ] При передаче анонимного ключа вместо пользовательского токена возвращается HTTP 401 (`USER_TOKEN_REQUIRED`).- [ ] На фронтенде `base.ts` передает токен из `supabase.auth.getSession()`.- [ ] При истечении токена Supabase Client автоматически обновляет токен в фоне без прерывания работы пользователя.
