# Навык: Работа с миграциями Supabase на Windows

## Контекст и назначение
Используйте этот навык при создании, обновлении, синхронизации и применении миграций базы данных PostgreSQL через Supabase CLI в проекте.

---

## 1. Два рабочих процесса: db:push vs db:pull

В проекте поддерживаются два взаимодополняющих подхода:

| Сценарий | Команда | Что происходит |
|---|---|---|
| **Код -> База данных (Code-First)** | `npm run db:push` | Берёт локальные файлы из `supabase/migrations/` и накатывает их в удалённую БД. Используется, когда вы написали миграцию руками в коде. |
| **База данных -> Код (DB-First / Studio)** | `npm run db:pull` | Сравнивает схему удалённой БД с локальными файлами и **генерирует новый файл миграции** в `supabase/migrations/` со всеми изменениями, сделанными в браузере в Supabase Studio. |

### Золотое правило синхронизации:
- Если вы или разработчик создали/изменили таблицу **через браузер в Supabase Studio**:  
  👉 **Сразу выполните `npm run db:pull`**, чтобы изменения зафиксировались в коде репозитория и попали в git!
- Если вы написали SQL-файл миграции **в коде**:  
  👉 **Выполните `npm run db:push`**, чтобы применить его к удалённой базе данных.

## 2. Критическое правило: Окончания строк (Line Endings) в Windows

> [!CAUTION]
> **Всегда проверяйте, что файлы миграций используют `\n` (LF), а не `\r\n` (CRLF) или одиночный `\r` (CR)!**

### Проблема:
Supabase CLI и драйвер PostgreSQL (`pgx` в Go) на Windows при наличии некорректных переносов строк (особенно одиночного `\r`) могут воспринять весь SQL-файл как одну строку. В результате возникает ошибка:
```text
ERROR: cannot insert multiple commands into a prepared statement (SQLSTATE 42601)
```

### Решение и самопроверка:
При создании или редактировании `.sql` файлов миграций обязательно проверять и нормализовать переносы строк в LF:
```bash
node -e "const fs = require('fs'); const f = '02-lesson/supabase/migrations/<файл>.sql'; let c = fs.readFileSync(f, 'utf8').replace(/\r\n/g, '\n').replace(/\r/g, '\n'); fs.writeFileSync(f, c); console.log('LF OK:', !fs.readFileSync(f).includes(13));"
```

## 3. Стандарт структуры таблиц и миграций

Каждая новая таблица в проекте должна соответствовать стандартам:

1. **Первичный ключ:** `id bigint generated by default as identity not null primary key` (в TypeScript соответствует `id: number`).
2. **Временные метки:**
   - `created_at timestamp with time zone not null default now()`
   - `updated_at timestamp with time zone not null default now()` (для сущностей, подлежащих редактированию)
3. **Автообновление `updated_at` через триггер:**
   ```sql
   create or replace function public.update_<таблица>_updated_at()
   returns trigger as $$
   begin
       new.updated_at = now();
       return new;
   end;
   $$ language plpgsql;

   drop trigger if exists trigger_update_<таблица>_updated_at on public.<таблица>;
   create trigger trigger_update_<таблица>_updated_at
       before update on public.<таблица>
       for each row
       execute function public.update_<таблица>_updated_at();
   ```
4. **Индексы:** создавать индексы для внешних ключей, полей поиска и сортировок по дате (`created_at desc`, `updated_at desc`).
5. **Документирование:** добавлять `comment on table` и `comment on column`.

## 5. Доступные команды в package.json

Все команды запускаются из папки `02-lesson` (в Windows PowerShell используйте `npm.cmd`, если скрипты блокируются политикой):

```bash
cd 02-lesson

# Вытянуть изменения из базы данных в локальный файл миграции (после правок в браузере)
npm run db:pull

# Накатить все новые миграции на удалённую БД (Cloud / Production)
npm run db:push

# Пересоздать локальную БД и накатить все миграции с нуля (Local Dev)
npm run db:reset

# Привязать проект к Supabase Cloud
npm run db:link -- --project-ref <SUPABASE_PROJECT_ID>
```

## 6. Синхронизация типов с фронтендом

После добавления таблицы создайте или обновите TypeScript интерфейс в `frontend/src/.../model/`:
- Имена полей совпадают со схемой БД (`snake_case`).
- `bigint` / `integer` -> `number`.
- `timestamptz` -> `string` (ISO формат).
- Nullable-поля в БД -> `Type | null`.
