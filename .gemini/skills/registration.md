# Навык: Регистрация пользователей в Supabase и валидация форм (React Hook Form)## КонтекстИспользуйте этот навык при разработке компонентов регистрации новых пользователей, валидации учетных данных через `react-hook-form`, обработке подтверждения Email и автоматической инициализации профилей пользователей в базе данных PostgreSQL.---## Основные принципы1. **Клиентская валидация через React Hook Form**:   - Поля регистрируются через хук `useForm<T>()` с режимом валидации `mode: 'onTouched'`.   - Проверка формата Email через регулярное выражение.   - Минимальная длина пароля (не менее 6 символов по умолчанию в Supabase).   - Валидация совпадения паролей (`confirmPassword === password`) с помощью функции `getValues('password')`.2. **Вызов Supabase `signUp`**:   - Метод `supabase.auth.signUp({ email, password, options })`.   - Возможность передачи метаданных пользователя (`options.data: { full_name, role }`), которые сохраняются в `raw_user_meta_data`.3. **Два сценария завершения регистрации**:   - **С подтверждением Email (Email Confirmation ON)**: `session` возвращается как `null`, создается неподтвержденный `user`. Пользователю показывается информационное сообщение: «Проверьте вашу почту для активации аккаунта».   - **Без подтверждения Email (Email Confirmation OFF)**: сразу создается активная `session`, генерируются токены, срабатывает событие `onAuthStateChange('SIGNED_IN')`, пользователь мгновенно авторизуется.4. **Синхронизация с таблицей профилей (PostgreSQL Trigger)**:   - Вся бизнес-информация о пользователе (имя, аватар, баланс, настройки) должна храниться в таблице `public.profiles`.   - Создание профиля выполняется автоматически системным триггером базы данных при добавлении записи в `auth.users`.---## Руководство по реализации### 1. Компонент формы регистрации с React Hook Form```typescriptimport React, { useState } from 'react';import { useForm } from 'react-hook-form';import { useAuthStore } from '../model/authStore';interface SignUpFormData {  email: string;  password: string;  confirmPassword: string;  fullName?: string;}export const SignUpForm: React.FC<{ onSuccess?: () => void }> = ({ onSuccess }) => {  const [serverError, setServerError] = useState('');  const [successNotice, setSuccessNotice] = useState('');  const { signUp } = useAuthStore();  const {    register,    handleSubmit,    getValues,    formState: { errors, isSubmitting },  } = useForm<SignUpFormData>({    mode: 'onTouched',  });  const onSubmit = async (data: SignUpFormData) => {    setServerError('');    setSuccessNotice('');    const { error, message } = await signUp(data.email, data.password);    if (error) {      setServerError(error);    } else if (message) {      setSuccessNotice(message);    } else {      onSuccess?.();    }  };  return (    <form onSubmit={handleSubmit(onSubmit)} noValidate>      {serverError && <div className="error-banner">{serverError}</div>}      {successNotice && <div className="success-banner">{successNotice}</div>}      <div className="form-field">        <label>Email</label>        <input          type="email"          disabled={isSubmitting}          {...register('email', {            required: 'Введите email адрес',            pattern: {              value: /^[A-Z0-9._%+-]+@[A-Z0-9.-]+\.[A-Z]{2,}$/i,              message: 'Некорректный формат email адреса',            },          })}        />        {errors.email && <span className="field-error">{errors.email.message}</span>}      </div>      <div className="form-field">        <label>Пароль</label>        <input          type="password"          disabled={isSubmitting}          {...register('password', {            required: 'Введите пароль',            minLength: {              value: 6,              message: 'Пароль должен содержать минимум 6 символов',            },          })}        />        {errors.password && <span className="field-error">{errors.password.message}</span>}      </div>      <div className="form-field">        <label>Подтверждение пароля</label>        <input          type="password"          disabled={isSubmitting}          {...register('confirmPassword', {            required: 'Повторите пароль',            validate: (val) => val === getValues('password') || 'Пароли не совпадают',          })}        />        {errors.confirmPassword && (          <span className="field-error">{errors.confirmPassword.message}</span>        )}      </div>      <button type="submit" disabled={isSubmitting}>        {isSubmitting ? 'Регистрация...' : 'Зарегистрироваться'}      </button>    </form>  );};```### 2. Метод `signUp` в сторе авторизации```typescriptsignUp: async (email: string, password: string) => {  try {    const { data, error } = await supabase.auth.signUp({      email: email.trim(),      password,    });    if (error) {      return { error: formatAuthError(error.message) };    }    // Если email confirmation отключен, session вернется сразу    if (data.session) {      set({ session: data.session, user: data.session.user, loading: false });      return { error: null };    }    // Если требуется подтверждение по ссылке из письма    return {      error: null,      message: 'Регистрация успешна! Пожалуйста, проверьте почту для подтверждения аккаунта.',    };  } catch (err: unknown) {    const msg = err instanceof Error ? err.message : 'Ошибка при регистрации';    return { error: formatAuthError(msg) };  }}```### 3. Автоматическое создание профиля в БД (PostgreSQL Миграция)Для синхронизации зарегистрированных пользователей с таблицей `public.profiles`:```sql-- 1. Таблица публичных профилейCREATE TABLE IF NOT EXISTS public.profiles (  id UUID REFERENCES auth.users(id) ON DELETE CASCADE PRIMARY KEY,  email TEXT,  full_name TEXT,  avatar_url TEXT,  created_at TIMESTAMPTZ DEFAULT now() NOT NULL,  updated_at TIMESTAMPTZ DEFAULT now() NOT NULL);-- Включение RLS для таблицы профилейALTER TABLE public.profiles ENABLE ROW LEVEL SECURITY;CREATE POLICY "Пользователи могут читать любые профили"  ON public.profiles FOR SELECT USING (true);CREATE POLICY "Пользователи могут редактировать только свой профиль"  ON public.profiles FOR UPDATE USING (auth.uid() = id);-- 2. Функция создания профиля при регистрацииCREATE OR REPLACE FUNCTION public.handle_new_user()RETURNS TRIGGER AS $$BEGIN  INSERT INTO public.profiles (id, email, full_name, avatar_url)  VALUES (    new.id,    new.email,    new.raw_user_meta_data->>'full_name',    new.raw_user_meta_data->>'avatar_url'  );  RETURN new;END;$$ LANGUAGE plpgsql SECURITY DEFINER;-- 3. Триггер на добавление пользователя в auth.usersDROP TRIGGER IF EXISTS on_auth_user_created ON auth.users;CREATE TRIGGER on_auth_user_created  AFTER INSERT ON auth.users  FOR EACH ROW EXECUTE FUNCTION public.handle_new_user();```---## Чек-лист проверки формы регистрации- [ ] Поле `email` нормализуется (удаляются пробелы `.trim()`).- [ ] Ошибки валидации отображаются точечно под каждым невалидным полем без скачков верстки.- [ ] Совпадение паролей проверяется через `getValues('password')` (без лишних рендеров).- [ ] Типичные ошибки Supabase локализованы (*«Пользователь уже зарегистрирован»*, *«Слабый пароль»*).- [ ] Предусмотрена обработка подтверждения email (сообщение пользователю без блокировки интерфейса).
