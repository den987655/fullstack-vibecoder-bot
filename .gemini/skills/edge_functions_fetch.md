# Навык: Интеграция фронтенда и бэкенда через Supabase Edge Functions (без SDK)## КонтекстИспользуйте этот паттерн, когда нужно связать React/Vite фронтенд с базой данных Supabase, но архитектура явно **отказывается от использования Supabase Client SDK** в пользу обычных веб-запросов (HTTP `fetch`) к Edge Функциям.## Основные принципы1. **Без Supabase SDK на фронтенде:** `supabase-js` не устанавливается и не используется. Вся передача данных происходит через нативные `fetch` запросы.2. **Единая обертка API:** Все вызовы `fetch` проходят через общую функцию (`base.ts`), которая автоматически подставляет базовый URL и заголовки авторизации.3. **TanStack Query для управления состоянием:** Поскольку WebSockets (Supabase Realtime) без SDK недоступны, асинхронными запросами, кэшированием и "живым" обновлением управляет `@tanstack/react-query`.4. **Поллинг для "Реального времени":** Синхронизация данных, имитирующая живое соединение, использует опцию `refetchInterval` из React Query.## Руководство по реализации### 1. Обертка API (`shared/api/base.ts`)Создайте корневую функцию `fetch`, которая подхватывает переменные окружения. Облачные URL-адреса и ключи авторизации (Anon Keys) берутся из `.env`.```typescriptexport const API_BASE_URL = import.meta.env.VITE_SUPABASE_FUNCTIONS_URL || 'http://localhost:54321/functions/v1';export const fetchApi = async <T>(endpoint: string, options?: RequestInit): Promise<T> => {  const url = `${API_BASE_URL}${endpoint}`;    const headers: Record<string, string> = {    'Content-Type': 'application/json',  };  // Если у нас в .env указан ANON_KEY, передаем его  const anonKey = import.meta.env.VITE_SUPABASE_ANON_KEY;  if (anonKey) {    headers['Authorization'] = `Bearer ${anonKey}`;  }  if (options?.headers) {    Object.assign(headers, options.headers);  }  const response = await fetch(url, { ...options, headers });  if (!response.ok) {    let errorMsg = 'Произошла ошибка при получении данных.';    try {      const errData = await response.json();      errorMsg = errData.error || errData.message || errorMsg;    } catch { /* Игнорируем ошибки парсинга JSON */ }    throw new Error(errorMsg);  }  return response.json();};```### 2. Хуки React Query + Поллинг (`queries.ts`)Замените вебхуки (составляющую реального времени) на поллинг с помощью `refetchInterval`. Строго опишите TS интерфейсы, чтобы они полностью повторяли JSON ответ от Deno.```typescriptimport { useQuery } from '@tanstack/react-query';import { fetchApi } from '../../../shared/api/base';// Важно: Убедитесь, что типы точно совпадают с теми полями, что возвращает Edge функция (SQL)import type { Message } from '../model/messageTypes';export const useMessages = (dialogId: number | null) => {  return useQuery({    queryKey: ['messages', dialogId],    // Параметры передаются напрямую в URL Edge функции    queryFn: () => fetchApi<Message[]>(`/messages?clientId=${dialogId}`),    enabled: !!dialogId,    // Поллинг каждые 2 секунды позволяет обновлять UI без перезагрузки    refetchInterval: 2000,   });};```### 3. Настройка переменных окружения (`.env`)Убедитесь, что фронтенд содержит правильные ссылки для локальной разработки или продакшена.```env# URL в облаке SupabaseVITE_SUPABASE_FUNCTIONS_URL=https://<ВАШ_ID_ПРОЕКТА>.supabase.co/functions/v1# Ключ для защищенных функций (если функция залита без флага --no-verify-jwt)VITE_SUPABASE_ANON_KEY=eyJhbGciOiJIUzI1...```## Чек-лист для исправления ошибок белого экрана (UI Crashes)- Проверьте, в каком формате Edge Функции отдают ключи: `snake_case` (например `client_id`) или `camelCase`? TypeScript интерфейсы ДОЛЖНЫ строго мапиться с базой Postgres.- Проверьте числа и строки: если в базе ID типа `bigint` / `integer`, то в TypeScript это должен быть `number`, а не `string`.- Если возникает ошибка "Failed to fetch" (Не удалось загрузить ресурс), убедитесь, что `VITE_SUPABASE_FUNCTIONS_URL` работает и функции были успешно задеплоены.
