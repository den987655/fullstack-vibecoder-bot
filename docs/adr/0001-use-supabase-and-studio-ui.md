# ADR-0001: Использование Supabase и Supabase Studio (UI) в качестве Backend-платформы и среды управления данными## Метаданные- **Статус:** Accepted- **Дата:** 2026-10-13- **Авторы:** Команда разработки fullstack-vibecoder-bot- **Связанные документы / файлы:**  - Навык работы с миграциями: [.gemini/skills/supabase_migrations.md](file:///E:/react/fullstack-vibecoder/fullstack-vibecoder-bot/.gemini/skills/supabase_migrations.md)  - Навык сетевых запросов: [.gemini/skills/edge_functions_fetch.md](file:///E:/react/fullstack-vibecoder/fullstack-vibecoder-bot/.gemini/skills/edge_functions_fetch.md)  - Use Case обработки сообщений: [temp.ts](file:///E:/react/fullstack-vibecoder/fullstack-vibecoder-bot/temp.ts)  - Конфигурация Supabase: [02-lesson/supabase/config.toml](file:///E:/react/fullstack-vibecoder/fullstack-vibecoder-bot/02-lesson/supabase/config.toml)---## 1. Контекст и проблематика (Context & Problem Statement)Проект **fullstack-vibecoder-bot** представляет собой гибридную систему коммуникации оператора с Telegram-клиентами. Система состоит из трех ключевых частей:1. **Telegram-бот с чистой архитектурой** (Deno Edge Function `clean-architecture-bot` / Use Cases, такие как [HandleMessageUseCase](file:///E:/react/fullstack-vibecoder/fullstack-vibecoder-bot/temp.ts)), обрабатывающий сообщения пользователей, конвертацию валют и нажатия инлайн-кнопок.2. **Панель оператора** (React 19 + TypeScript + Vite 8 + TanStack Query + Zustand), отображающая список диалогов и историю сообщений в реальном времени.3. **Слой постоянного хранения данных** (сообщения, клиенты, логи диалогов).### Проблемы и требования к платформе:- **Скорость прототипирования и разработки:** Требовалось решение, устраняющее необходимость написания сотен строк шаблонного CRUD-кода для управления БД.- **Полноценная реляционная СУБД:** Необходима надежная транзакционная база данных (PostgreSQL) с внешними ключами, триггерами (`updated_at`), индексами и поддержкой сложных выборок.- **Удобный визуальный интерфейс (Supabase Studio / UI):** Разработчикам и операторам необходим удобный дашборд (порт 54323 локально или облачная консоль) для просмотра содержимого таблиц `public.clients` и `public.messages`, выполнения SQL-скриптов, проверки прав доступа (RLS) и включения репликации публикаций без сторонних утилит вроде pgAdmin или DBeaver.- **Серверные бессерверные функции (Serverless):** Возможность деплоить изолированные функции (вебхук Telegram-бота, эндпоинты `/client` и `/messages`) без администрирования отдельных VPS-серверов.---## 2. Рассмотренные альтернативы (Considered Options)### Вариант 1: Классический собственный бэкенд (Node.js Express / NestJS + PostgreSQL на VPS)- **Плюсы:**  - Полный контроль над архитектурой сервера, пайплайнами и middleware.- **Минусы:**  - Высокие трудозатраты на развертывание, настройку Docker, Nginx, SSL-сертификатов, CI/CD, резервного копирования.  - Необходимость самостоятельной разработки панели администрирования данных либо постоянного использования локальных SQL-клиентов.  - Высокая стоимость поддержки для небольшого проекта на начальных этапах.### Вариант 2: Firebase / Google Cloud Firestore (NoSQL BaaS)- **Плюсы:**  - Быстрый старт, встроенная подписка на данные в реальном времени.  - Готовый веб-интерфейс для просмотра коллекций.- **Минусы:**  - Документоориентированная NoSQL модель не подходит для реляционных структур данных диалогов (клиенты, сообщения, связанные события).  - Отсутствие стандартного SQL, сложность выполнения аналитических и агрегирующих запросов.  - Жесткий вендор-лок на экосистему Google Cloud.### Вариант 3: Supabase (BaaS на базе PostgreSQL + Studio UI + Edge Functions) — ВЫБРАНО- **Плюсы:**  - Открытый стандартный PostgreSQL (версия 15–17) с поддержкой всех расширений, индексов, функций PL/pgSQL и триггеров.  - **Supabase Studio (superbase.ui):** Встроенный мощный веб-интерфейс для визуального управления схемой данных, таблицами, SQL Editor, табличным просмотром и управлением публикациями Realtime.  - **Deno Edge Functions:** Бессерверная среда с нулевым временем холодного старта, поддержкой TypeScript из коробки, идеально подходящая для вебхуков Telegram-бота ([temp.ts](file:///E:/react/fullstack-vibecoder/fullstack-vibecoder-bot/temp.ts)).  - **Двунаправленный рабочий процесс миграций:** Поддержка создания таблиц через Studio UI с последующим экспортом в код (`npm run db:pull`) или написания SQL в репозитории с накатом в облако (`npm run db:push`).  - **Встроенный Realtime-движок:** Возможность слушать изменения таблиц через WebSockets напрямую из PostgreSQL WAL (Logical Replication).- **Минусы:**  - Зависимость от соглашений и форматов Supabase CLI.  - Необходимость контролировать перенос строк (LF) на Windows при работе с миграциями через CLI.---## 3. Принятое решение (Decision Outcome)Принять **Supabase** в качестве единой Backend- и Data-платформы проекта fullstack-vibecoder-bot.### Ключевые аспекты использования:1. **База данных:** PostgreSQL в Supabase Cloud (с локальным зеркалом в Docker через `npx supabase start`).2. **Supabase Studio UI (superbase.ui):** Используется для:   - Мониторинга поступающих от бота сообщений и клиентов в реальном времени.   - Экспресс-прототипирования таблиц и проверки структуры перед фиксацией в коде.   - Управления публикациями `supabase_realtime` и политиками безопасности RLS.3. **Бессерверные функции:** Deno Edge Functions для вебхука Telegram-бота (`clean-architecture-bot`) и REST API для панели оператора.4. **Управление схемой:** Строго через систему миграций Supabase CLI (`db:push` и `db:pull`), описанную в [.gemini/skills/supabase_migrations.md](file:///E:/react/fullstack-vibecoder/fullstack-vibecoder-bot/.gemini/skills/supabase_migrations.md).---## 4. Последствия и компромиссы (Consequences)### Положительные:- Сокращение времени разработки инфраструктуры бэкенда на 80%.- Удобство отладки: разработчик всегда может открыть Supabase Studio UI (`http://localhost:54323` или панель в браузере) и сразу увидеть, как `HandleMessageUseCase` ([temp.ts](file:///E:/react/fullstack-vibecoder/fullstack-vibecoder-bot/temp.ts)) сохраняет строки в `public.clients` и `public.messages`.- Масштабируемость без необходимости администрирования серверов.- Фундамент для бесшовного включения Realtime через логическую репликацию Postgres.### Отрицательные и компромиссы:- Необходимость дисциплины: любые изменения, внесенные через Studio UI, должны немедленно подтягиваться в репозиторий через `npm run db:pull`.- На фронтенде в первой версии сохранялся запрет на прямое использование тяжелого `@supabase/supabase-js` SDK в пользу легких `fetchApi` запросов к Edge Functions, что потребовало отдельного архитектурного решения при переходе на Realtime (см. [ADR-0002](file:///E:/react/fullstack-vibecoder/fullstack-vibecoder-bot/docs/adr/0002-transition-to-realtime-messages.md)).---## 5.
