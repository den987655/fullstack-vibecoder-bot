# AGENT & PROJECT INSTRUCTIONS (agent.md)Документ описывает структуру, архитектуру, стек технологий, правила разработки и команды запуска для проекта **fullstack-vibecoder-bot**.---## 1. Обзор проекта и стек технологийПроект представляет собой fullstack-мессенджер для взаимодействия оператора с Telegram-клиентами через Telegram-бота и панель оператора.### Стек технологий:- **Frontend (`02-lesson/frontend`)**:  - React 19 + TypeScript + Vite 8  - **Feature-Sliced Design (FSD)**: с подходом **local-first** (без создания лишних глобальных слоев `entities` / `widgets`, если сущности принадлежат конкретной странице).  - **TanStack Query (React Query v5)**: управление асинхронным состоянием, кэшированием и данными диалогов.  - **Zustand**: клиентский глобальный стор без prop-drilling (`messengerStore.ts`).  - **Без Supabase Client SDK для базового REST**: стандартные запросы к Edge Functions выполняются через обычный `fetch` (`src/shared/api/base.ts`).  - **Supabase Realtime**: подписка на входящие сообщения через WebSockets / публикации PostgreSQL.- **Backend / Edge Functions (`02-lesson/supabase/functions`)**:  - Deno + TypeScript  - `clean-architecture-bot`: обработчик вебхука Telegram-бота (чистая архитектура).  - `client`: REST-эндпоинт для получения списка клиентов (диалогов).  - `messages`: REST-эндпоинт для получения истории сообщений.- **База данных**:  - PostgreSQL (Supabase Cloud или локальный Supabase).  - Таблицы: `public.clients`, `public.messages`.- **CI/CD**:  - GitLab CI (`.gitlab-ci.yml`) — автодеплой функции `clean-architecture-bot` в Supabase Cloud.---## 2. Команды для запуска и разработки### Быстрый запуск с облачным Supabase (Production Cloud)1. Убедитесь, что в `02-lesson/frontend/.env` прописан рабочий URL:   ```env   VITE_SUPABASE_FUNCTIONS_URL=https://phnupivthxtoxtslvmlr.supabase.co/functions/v1   ```2. Перейдите в папку фронтенда и запустите dev-сервер:   ```bash   cd 02-lesson/frontend   npm install   npm run dev   ```3. Откройте приложение: `http://localhost:5173`.### Локальный запуск через Supabase CLI (Offline / Local Dev)1. Запустите стек Supabase (требуется Docker):   ```bash   cd 02-lesson   npx supabase start   ```2. Запустите Edge Functions:   ```bash   npx supabase functions serve   ```3. В `02-lesson/frontend/.env` переключите URL:   ```env   VITE_SUPABASE_FUNCTIONS_URL=http://localhost:54321/functions/v1   ```4. Запустите фронтенд:   ```bash   cd 02-lesson/frontend   npm run dev   ```### Деплой Edge Functions в Cloud вручную:```bashcd 02-lessonnpx supabase functions deploy client --no-verify-jwt --project-ref <SUPABASE_PROJECT_ID>npx supabase functions deploy messages --no-verify-jwt --project-ref <SUPABASE_PROJECT_ID>npx supabase functions deploy clean-architecture-bot --project-ref <SUPABASE_PROJECT_ID>```---## 4. Архитектурные правила и соглашения для Агента1. **Язык общения и комментариев:**    - Все ответы, описания и комментарии к коду должны быть исключительно на **русском языке**.2. **FSD Local-First подход:**   - Не создавайте глобальные слои `entities/` или `widgets/` без явной необходимости повторного использования на разных страницах.   - Локальные компоненты, типы и API-запросы страницы должны жить внутри директории этой страницы (например, `pages/messenger/{ui,api,model}`).3. **Строгая синхронизация типов с БД:**   - Интерфейсы TypeScript должны строго отражать схему таблиц PostgreSQL (snake_case, числовые `id: number` вместо `string`).4. **Сетевые запросы:**   - Базовые запросы REST должны маршрутизироваться через централизованную функцию `fetchApi` из `shared/api/base.ts`.5. **Realtime / Обновление данных (ADR-0002):**   - Ранее в проекте использовался периодический опрос (polling) в TanStack Query (`refetchInterval: 2000`).   - Принято архитектурное решение (см. `docs/adr/0002-transition-to-realtime-messages.md`) о переходе на **Supabase Realtime (WebSockets)** через публикацию `supabase_realtime` на таблице `public.messages`.   - Новые сообщения от Telegram-бота ([temp.ts](file:///E:/react/fullstack-vibecoder/fullstack-vibecoder-bot/temp.ts)) доставляются в панель оператора через сокет-подписку без задержки.6. **Архитектурные решения (ADR, навык `.gemini/skills/adr.md`):**   - Все значимые архитектурные и инфраструктурные решения (выбор библиотек, баз данных, протоколов связи, отказ от подходов) должны фиксироваться в `docs/adr/` согласно стандарту.
